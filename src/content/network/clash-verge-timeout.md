faq:
  - q: Clash Verge 节点全部超时，最该先查什么？
    a: 先分清「假超时」和「真超时」：点节点组的测速图标全红，但网页实际能打开——是测速地址失效（假超时），换测速 URL 即可；网页也打不开才是真超时，按「内核状态→订阅状态→系统时间→DNS」顺序排查。
  - q: 什么是测速地址失效？怎么改？
    a: Clash 用一个 URL 测节点延迟，默认地址如果被墙或被目标站屏蔽，所有节点都会显示超时，但实际代理是通的。在设置中把测速地址改为 http://www.gstatic.com/generate_204 或 http://cp.cloudflare.com/generate_204 再测。
  - q: Clash Verge 内核没启动是什么表现？
    a: 首页内核状态异常、端口显示为空、所有开关打不开。常见原因：端口被占用（改端口或关闭占用程序）、内核文件被杀毒软件删除（恢复并加白名单）、TUN 模式残留导致启动失败（关闭 TUN 后重启客户端）。
  - q: 订阅在别的客户端能用，在 Clash 里全超时？
    a: 大概率是订阅格式问题：该订阅不是 Clash 格式，或包含 Clash 内核不支持的协议（如部分新协议需要 Meta/mihomo 内核）。解决：在机场后台选择 Clash 专用订阅链接，或把 Clash Verge 切换到 Meta 内核，或联系客服要通用格式。
  - q: 开了 TUN 模式后反而全部断网怎么办？
    a: TUN 模式故障的典型表现。依次：确认以管理员身份运行、重装虚拟网卡驱动（设置中有重置按钮）、关闭 TUN 恢复系统代理模式。TUN 残留的虚拟网卡有时需要在系统网络适配器里手动禁用删除。
  - q: 上面都试了还是全红怎么办？
    a: 回到通用排查：订阅是否过期/流量耗尽（后台查）、系统时间是否准确、换网络交叉测试、更新订阅拉取新节点、临时关闭防火墙杀毒。全部无效则可能是机场入口被封，见通用超时排查文章或联系机场客服。

**直接答案：Clash Verge 节点全部超时，先做一个 10 秒判断——网页能不能实际打开？能打开就是「假超时」（测速地址失效，换成 `http://www.gstatic.com/generate_204` 即可）；打不开再按「内核 → 订阅格式 → 通用原因」排查。**

通用性原因（订阅过期、系统时间、本地网络）见 [机场节点全部超时总排查](/network/nodes-all-timeout/)，本文专讲 **Clash 特有**的几个坑。

## 第一步：排除「假超时」

Clash 的延迟测试依赖一个测速 URL。**默认测速地址被墙或被屏蔽时，所有节点显示超时，但代理实际是通的。**

判断：直接开浏览器访问外网。能开 → 假超时，进设置把测速地址改为：

```
http://www.gstatic.com/generate_204
```

或 `http://cp.cloudflare.com/generate_204`。改完重测，问题消失。

## 第二步：检查内核状态

Clash Verge 是「界面 + 内核」结构，**界面开着不代表内核在跑**。首页看内核状态与端口：

| 异常 | 原因 | 处理 |
| ---- | ---- | ---- |
| 端口为空 / 内核未运行 | 端口被占用 | 改端口或关掉占用程序 |
| 内核文件丢失 | 杀毒软件误删 | 恢复文件 + 加入白名单 |
| 启动即崩溃 | TUN 残留 / 配置损坏 | 关 TUN 重启；删除损坏配置 |

## 第三步：订阅格式问题（Clash 专属坑）

同一份订阅在 v2rayN 能用、在 Clash 全超时？三种可能：

1. **订阅不是 Clash 格式**：机场后台通常有多种订阅链接，选 Clash 专用的那条
2. **协议不被当前内核支持**：部分新协议需要 Meta（mihomo）内核——Clash Verge Rev 设置里切换到 Meta 内核
3. **需要通用订阅**：联系机场在线客服获取（本站 [Clash 机场推荐](/reviews/best/clash/) 中的品牌均支持订阅导入，部分需客服开通）

## 第四步：DNS 与 TUN

- **DNS**：设置中启用 fake-ip 模式，或把 DNS 改为 `1.1.1.1`——DNS 污染会造成部分节点异常
- **TUN 故障**：开 TUN 后全断网是典型症状——确认管理员运行、重置虚拟网卡驱动、必要时关闭 TUN 回到系统代理模式

## 第五步：回到通用清单

Clash 特有原因排除后仍全红，走通用流程：

1. 后台查订阅状态（过期/流量）
2. 同步系统时间
3. 换网络交叉测试（Wi-Fi ↔ 流量）
4. 更新订阅
5. 关防火墙/杀毒测试

完整步骤见 [机场节点全部超时总排查](/network/nodes-all-timeout/)。

## 判断标准

节点延迟测出数值、网页实际可开即解决。顺手做两件事：把测速地址固定为 generate_204、设置订阅自动更新（24h）。
